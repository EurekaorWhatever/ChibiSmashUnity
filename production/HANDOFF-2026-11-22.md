### How to run the 2-instance tests again

1. Build a Windows **development** player (Unity MCP `BuildPipeline.BuildPlayer`, `BuildOptions.Development`).
2. Start it: `ChibiClash.exe -screen-fullscreen 0 -autoAcceptInvites` (or `-autoMatchmake`, or `-autoJoinLobby CODE`).
3. In the editor, enter Play Mode and call `DevCreateLobby("Test")` then `DevInvite("DevGuest")` (or `DevMatchmake()`).
4. **The Unity editor window must have focus**, or Play Mode stops advancing. Bring it to the front with
   `(New-Object -ComObject WScript.Shell).AppActivate(<Unity pid>)`. Never edit scripts during Play Mode: Unity
   recompiles and the running match breaks (NullReferenceExceptions in `ChibiAudio` / `StageAtmosphere`).

## NEXT: the user's new spec ("Claude prompt.pdf", 2026-11-22). Not started

1. **Vs Online**: up to **4 players**, all against each other, paired by the player name typed at first launch.
2. **Vs Local**: rooms with **min 2, max 4** players, all against each other.
   - With no room yet, the middle of the screen says **"No room create yet!"**.
   - The top-right buttons are **"Create Rooms"** and **"Join room"**.
   - Create opens a pop-up, **"Enter the room name"**. The room is created automatically and shown as a room block.
   - Clicking the block shows the **room code** and **invite player** (type a friend's name, which is the device
     identity).
   - Join room opens a pop-up, **"enter the room code"**.
3. **Vs CPU**: the player chooses a character, the CPU gets a random one, 1v1, and the player picks the difficulty
   **easy / medium / hard**. `Save.settings.cpuDifficulty` already exists and is in SETTINGS; it needs to be in the
   Vs CPU flow.
4. **Names**:
   - The name is the player's identity, linked to the device and used for pairing.
   - The name box appears only on first launch, and there is a **change-name** button.
   - The name must be **unique worldwide**: show "this name is already taken" and ask for another.
   - Offer **random name suggestions**.
   - Record every name and the player-join count in one place.
5. Everything must be playable, high quality and secure.

### Background for those decisions

- **4 players** means a change to the fighting engine: `ChibiSimulation` holds 2 fighters, and the input packets,
  rollback, HUD, camera and CPU all assume 2. The plan in `docs/architecture/netcode/four-player-design.md` touches
  about 90 places and takes several weeks of agent work. It also changes combat code, which the user said not to touch
  without asking.
- **Unique names worldwide** need a server-side store. Lobby cannot guarantee uniqueness. Options:
  - **Cloud Code** (a small script that reserves a name atomically) plus **Cloud Save** (the name registry and player
    count). This needs a free UGS service that the user turns on in the dashboard.
  - Without them, names can only be "checked against players online right now", which is not unique.
- "Local" in the PDF describes online rooms (codes, inviting by name). Confirm whether rooms move from Vs Online to
  Vs Local, and whether Vs Local keeps same-keyboard 1v1 too.
